# گزارش بررسی پیش از عرضه — ۱۵ نوامبر ۲۰۲۶

وضعیت: مناسب ادامهٔ آزمون داخلی؛ هنوز آماده عرضه عمومی با قابلیت «پایش خودکار ترب» نیست. نبود منبع مجاز داده رقبا تنها مانع نیست؛ گردش پرداخت، بازیابی حساب و عملیات پس‌زمینه نیز هنوز کامل نیستند.

## نتیجهٔ بررسی‌های اجراشده

| بررسی | نتیجه و حدود اعتبار |
|---|---|
| موتور قیمت، کیفیت داده و اتصال‌ها | ۹۹ آزمون واحد موفق؛ شامل تفکیک تنوع‌ها و منع نوشتن رابط |
| امنیت API، رقابت تغییر توکن ترب، مرز روز تهران و فقط‌خواندنی | ۱۴ آزمون موفق |
| قواعد نگهداری worker | ۱ آزمون موفق؛ اتصال Redis اجرا نشده |
| HTTP و PostgreSQL واقعی | ۲۱ سناریو موفق؛ runner با parent تعداد ۲۲ را نمایش می‌دهد |
| OTP با PostgreSQL واقعی | ۶ سناریو موفق؛ runner با parent تعداد ۷؛ ارسال پیامک کاملاً محلی و بدون شبکه |
| جمع سناریوهای مستقل SaaS | ۱۴۱؛ parent test و تست نمونهٔ WordPress در این عدد نیست |
| رابط اختصاصی WordPress | ۱۳ بررسی امنیتی PHP در محیط شبیه‌سازی‌شده + lint موفق؛ نصب staging هنوز انجام نشده |
| فروشگاه زنده FixBoxIran | تشخیص ارتباط افزونه ترب سالم؛ نمونه ۱۰ محصول با GET خوانده شد: ۸ تطابق، ۲ محصول متغیر نیازمند بررسی؛ صفر نوشتن قیمت |
| TypeScript، ESLint، ساخت Next و راه‌اندازی standalone | موفق؛ دارایی‌ها و فونت محلی از سرور مستقل ارائه می‌شوند |
| وابستگی‌های runtime | pnpm audit --prod در این بررسی صفر advisory گزارش کرد؛ معادل ممیزی کامل امنیت نیست |
| مرورگر | ورود، تعرفه، کارت‌های اتصال و فرم افزونه در عرض ۳۹۰ بررسی شدند؛ فوکوس اولیه، Tab/Shift+Tab، Escape و بازگشت فوکوس اصلاح و بررسی شد. تمام صفحات/نقش‌ها جامع تأیید نشده‌اند |
| Docker، CI، Redis، پشتیبان‌گیری/بازیابی و بار تولید | هنوز اجرا نشده‌اند |

آزمون HTTP شامل جداسازی دو سازمان، کنترل عضویت، جلوگیری از CSRF، محدودیت دسترسی مدیریت، ذخیره محرمانه توکن ترب، رد مبلغ boolean، کاتالوگ، پیش‌نمایش قیمت، منع اجرای بازار ناقص و خروج از نشست است. OTP شامل مصرف هم‌زمان، عدم استفاده مجدد، انقضا، تعداد تلاش، فاصله ارسال و توقف ثبت‌نام است.

## ترب؛ آنچه واقعاً آماده است

- آداپتور خواندن Shop API رسمی، توکن Bearer فقط در header، قیمت صریحاً تومان، pagination محدود و تشخیص دور، ادغام شناسه‌های تکراری و اعتبارسنجی پاسخ.
- جلوگیری از دنبال کردن صفحه‌بندی خارج از دامنه رسمی و از افشای توکن؛ خطاهای ۴۰۱/۴۰۳/۴۲۹ و پاسخ ناقص موفق ثبت نمی‌شوند.
- ذخیره AES-GCM در سرور، تفکیک سازمان‌ها، عدم بازگرداندن توکن و مقابله با تعویض توکن حین درخواست.
- صفحه تنظیم اتصال و دریافت محصولات خود فروشگاه؛ این داده به‌عنوان قیمت رقبا وارد موتور نمی‌شود.
- کنترل تفاوت تعداد اعلام‌شده/جمع‌آوری‌شده، فروشندگان، تازگی و تناقض کمینهٔ قیمت؛ نمونهٔ ۲۰۹ پیشنهاد در برابر ۶ رکورد همچنان ناقص و غیرقابل اجراست.

کاربر بعداً دسترسی WordPress فروشگاه متصل به ترب را برای بررسی فقط‌خواندنی داد. سلامت ارتباط افزونه و نمونه کاتالوگ زنده بررسی شد؛ جزئیات در fixbox-readonly-review.md است. این دسترسی، توکن Shop API یا مجوز داده رقبا نیست. مستندات Shop API بررسی‌شده، دسترسی رقبا را مستند نمی‌کند. پیش از وعده تجاری باید منبع مجاز داده رقبا و پوشش واقعی آن تأیید شود. [مستندات رسمی ترب](https://github.com/torob/Torob-Sync/blob/main/shop_api.md)

## اصلاحات این مرحله

مرز روز کنترل مالی به Asia/Tehran منتقل شد. اجرای محصول ناموجود یا محصول واردشده با هزینه/کف صفر مسدود شد. وضعیت واقعی اتصال‌ها جای متن ثابت UI را گرفت. فرم ورود موبایل، منوی عمومی موبایل، چیدمان تعرفه و نام‌گذاری گروه کنترل‌ها اصلاح شد. ادعای آماده بودن CSV از راهنما حذف شد. مسیر توسعه API از خروجی TypeScript استفاده می‌کند تا metadata موردنیاز Nest حفظ شود. راه‌انداز standalone وب، سرویس وب در Compose، عبور API_INTERNAL_URL از Turbo، و workflow بررسی در GitHub اضافه شدند.

Compose برای PostgreSQL 18.7 به‌روز شد؛ PostgreSQL محلی آزمون‌ها همچنان 18.6 است. راهنمای رسمی ۱۲ نوامبر اصلاحات امنیتی را اعلام کرده است؛ ارتقای واقعی و بررسی مراحل پس از ارتقا روی staging باید انجام شود. [اعلان رسمی PostgreSQL](https://www.postgresql.org/about/news/postgresql-187-1712-1616-1520-1425-and-19-rc-2-released-3442/)

## موانع عرضه اشتراکی

1. **داده رقبا:** قرارداد/مجوز، واحد پول، تطبیق گونه و پوشش نمونه‌های واقعی ترب؛ امکان فنی خرید سرور جای این مرحله را نمی‌گیرد.
2. **عملیات قیمت:** صف پایدار چندسازمانی، سهمیه و زمان‌بندی، رسیدگی به اجرای نامعلوم، reconciliation و بازگردانی کنترل‌شده. worker فعلی تنها نگهداری رکوردهای امنیتی است.
3. **فروش اشتراک:** چرخه صورتحساب/پرداخت/تمدید/لغو، callback تکراری و تسویه، پایان اشتراک و ثبت مصرف باید تکمیل و آزمایش شوند. محاسبه تعرفهٔ فعلی پرداخت ایجاد نمی‌کند.
4. **حساب و امنیت:** بازیابی رمز، تأیید ایمیل، MFA مدیر، دعوت اعضا، سیاست حذف/نگهداری و تقویت قیدهای بین‌سازمانی/RLS باقی است.
5. **زیرساخت:** اجرای staging لینوکسی، TLS، صف Redis واقعی، آزمایش بازیابی از نسخه خارج سرور، بار، مانیتورینگ و تمرین توقف اضطراری.
6. **آزمون زنده:** فروشگاه staging مجاز و حساب ملی‌پیامک/الگو؛ عدم وجود credential نباید با موفقیت ساختگی جایگزین شود.
7. **افزونه مشتری:** بسته آزمایشی فقط‌خواندنی و مسیر اتصال سامانه ساخته شد؛ نصب staging واقعی، سازگاری Woo/WordPress، وبهوک، همگام‌سازی حذف‌ها، ارتقا و پشتیبانی انتشار باقی است. نصب روی فروشگاه اصلی انجام نشده است.

این موارد مانع اعلام «تقریباً آماده فروش با امکانات کامل» هستند؛ گزارش برای روشن کردن همان فاصله تهیه شده است. برای ادامه به NEXT-STEPS.md و server-sizing.md مراجعه شود.

فرمان کامل `pnpm check` پس از تغییرات موفق بود. بسته افزونه از سرور محلی با HTTP 200 دریافت و تطابق بایت و SHA-256 آن با فایل ساخته‌شده تأیید شد. تصاویر فرم در evidence/bridge-connection-form.jpg و evidence/bridge-mobile.jpg هستند. حساب و سازمان خالی و موقت آزمون مرورگر پس از خروج، با تطبیق شناسه/ایمیل دقیق پاک شدند.
